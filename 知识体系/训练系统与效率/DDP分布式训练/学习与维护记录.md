## 本次明确的技术边界

- backward 是标准 DDP 梯度同步主阶段，不是唯一通信阶段；保留初始化、buffer、SyncBatchNorm、自定义及日志通信。
- torchrun 创建训练子进程后，子进程各自初始化；不混淆 rank 与 DataLoader worker。
- Dataset、Sampler、BatchSampler、collate 分工及 Map-style / Iterable-style 差异。
- 同步梯度与本地更新的等价前提；Adam 状态一致性与参数平均反例。
- no_sync 覆盖 forward / backward；累计尾部按实际样本权重处理。
- AMP、裁剪、更新、scheduler 顺序；使用 optimizer post-hook 区分成功更新。
- 预取先取整个累计窗口只用于清楚展示权重，已在正文明确其内存与流水线影响。

以上为教程内容整理，不代表用户已独立掌握各项知识，不代写个人理解。

## 验证结果

本机 PyTorch 2.8.0，无 CUDA 验证条件。

1. Python 语法编译检查通过。
2. CPU/Gloo，2 rank，各 2 worker，38 个样本，每 rank batch=4，累计=4，2 epoch：通过。每 rank 19 个样本形成 5 micro-batch，两次更新 / epoch，累计 4 次成功更新；scheduler.last_epoch=4；保存参数有限。
3. 独立数值对照：相同初始 MLP 与 AdamW，比较 DDP 先累计同步后更新和单进程全局 batch 参考。窗口分别为每 rank 16、3 个样本；梯度与更新参数在 rtol=2e-5、atol=1e-7 内一致。
4. 14 张图自动检查文本边界，检查缩略总览及重叠时间线，无截断。Markdown 图路径和正文内嵌代码一致性检查通过。
