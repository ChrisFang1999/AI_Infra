## 当前进展

已形成训练报错的初步排查链路：多机日志、GPU 状态、平台事件、硬件监控、跨 rank 堆栈。已新增[通信等待型 GPU Hang 专题](训练卡住排查：通信等待型GPU_Hang.md)，涵盖机制、常见原因及恢复验证；尚未覆盖全部故障分支，也未开展新实验。

用户明确的排查习惯：优先找明确代码或 I/O 异常；堆栈分组是主要入口，通过连续快照识别偏离 rank 的持续停留，同时关联报错和系统日志。这里记录实际经验，不据此评定学习掌握程度。

## 堆栈定位后的诊断路径补充

已在 GPU Hang 专题内补两条路径：多数 GPU 100%／少数 0% 时调查 CPU 计算、数据队列、明确代码异常和跳过通信；全部 GPU 100% 时检查通信匹配、并行策略消融和 IB 状态。CPU 抓栈不能直接代表 GPU 执行位置，已修正通信等待必然呈现 allreduce 堆栈的表述。

DataLoader 案例同时包含显式异常与 getitem 捕获异常后替代数据不正确；ZeRO 切换记录为已有效的规避方案，未确认根因。本次仅整理知识文档，博客待同步。
